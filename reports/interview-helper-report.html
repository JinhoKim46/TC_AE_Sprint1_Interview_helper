Key decisions

One rule runs through all of them: the model judges, code computes. Models decide what to ask and how good an answer is; code counts, weighs, enforces limits and sets thresholds.

Prompt comparison (R4)

Five interviewer prompts, each the zero-shot baseline plus one technique, interviewed a simulated candidate playing three personas. Jev judged every transcript on rubric §12. Switch the measure to see the trade-offs.

Measure:

A re-run after a shared-prompt fix made turns 20–28% shorter. It did not reproduce P4's apparently adaptive follow-ups (2 / 2 / 6 became 4 / 4 / 4), so P2, P4 and P5 are treated as tied. Full details: docs/05-prompt-comparison.md.

Risks and limitations

None blocks the review. Judge variance and the small evaluation sample are the most likely reviewer questions and should be raised first.

Next steps

The next step is not more features. Run the app end to end with one real application, rehearse the review, and close three decisions. Ticks are remembered in this browser.

After the review, in order of value for long-term use

  1. History and progress dashboard: past interviews, score trend, recurring weak spots
  2. Live per-answer scoring with Jev, and a Coaching mode with tips and retries
  3. A larger evaluation set to calibrate the judge and separate P2, P4 and P5
  4. Voice: spoken questions and speech-to-text answers
  5. Login with MFA (draft PR #4), if the app is ever shared
  6. Interviewer avatars and JD import from URL, if still wanted
